# 도면 편집기 레퍼런스 조사 (타일 전문가 계산기 + 공용 평면 부품)

작성일: 2026년 10월 28일

- 목적: `/calc/tile-pro` 와 공용 2D 도면 부품(`src/components/plan/`)을 만들기 전에, 이미 있는 웹 평면·가구·타일 설계 도구가 어떻게 입력받고 무엇을 내보내는지 확인한다.
- 표기: "확인 못 함" = 공식 페이지·도움말·리뷰에서 근거를 찾지 못한 항목. 지어낸 내용 없음.
- 확인 방법: 공식 홈페이지·요금 페이지·도움말 문서·언론 기사·클리앙 사용기를 웹으로 직접 열람. 실제 앱을 손으로 조작해 본 것은 없음.

## 3. 특히 반영할 점

### (a) flatma 식 "대략 그린 뒤 치수 입력" 2단계
- 1단계 = 모양 고르기: 사각형 / ㄱ자 / 자유형 버튼. 자유형은 "벽 길이 → 꺾는 방향(왼/오)" 반복 입력. 그림은 즉시 비율대로 그려짐.
- 2단계 = 숫자 다듬기: 그림의 벽을 누르면 그 벽 길이 입력칸이 뜸(Planner 5D·ARCHISKETCH 방식). 손가락 그리기는 하지 않는다.
- 닫힘 검사: 자유형에서 마지막 점이 첫 점과 안 맞으면 차이(mm)를 빨간 글씨 한 줄로 보여주고 "마지막 벽 자동 맞춤" 버튼 제공(ARCHISKETCH 노란 점 경고 참고).
- 벽 치수 기준은 "안쪽 면(마감면)" 하나로 고정. 타일·장 물량은 안쪽 면이 기준이므로 중심선 선택지는 두지 않는다.

### (b) 결과물로 절단 목록·시공 도면 내보내기
| 계산기 | 결과물 | 참고 |
|---|---|---|
| 타일 | 배치 그림(온장 회색, 컷 색칠, 컷 치수 글씨), 컷 묶음 목록(같은 치수끼리 개수), 온장/컷 장 수·로스율·박스·줄눈재·접착제 | Layometry 컷 목록, TileWright 컷 강조 |
| 붙박이장 | 벽 정면도(칸 나눔·문짝), 판재 절단 목록(부품명·가로·세로·두께·개수·엣지 붙일 면), 원장 장 수 | flatma 재단 지도·엣지 길이·부품별 사양서 |
| 냉장고장 | 냉장고 자리+키큰장 정면도, 여유 치수(좌우·위 통풍 간격) 표시, 판재 절단 목록 | flatma 동일, IKEA 주방 가격 합계 즉시 갱신 |
- 형식: PNG 한 장 저장 + 주소 공유(보기 전용 링크, flatma와 같은 발상). 엑셀·DXF는 하지 않음(필요해지면 표를 CSV로 정도).
- 재단 지도(원장 위 배치 최적화)는 2차. 1차는 절단 목록과 원장 장 수 추정만.

### (c) 아파트 평면 불러오기
- 오늘의집·ARCHISKETCH·한샘은 아파트 단지별 실제 도면을 가진다. 우리는 그런 도면 DB가 없으므로 "단지 검색"은 하지 않는다.
- 대신 우리 견적 물량 DB(59/74/84 타입 62건)의 평면 비율로 "타입별 기본 방 치수 프리셋"을 만든다. 예: 84타입 욕실(공용) 가로·세로, 거실 바닥, 주방 벽 길이.
- 표시는 "84타입 평균값(표본 n건) — 실측으로 고치세요" 수준. 오늘의집이 치수 오차로 지적받았으므로, 프리셋은 시작점일 뿐이고 숫자 칸을 바로 열어 고치게 한다.
- 실제 프리셋 값은 DB에서 뽑아봐야 함 — 이 문서에서는 값 확인 못 함.
- 공개 화면 문구 규칙: 표본 수(예: 62건)는 공정·조건별로만, 출처 표기 금지 규칙 준수.

### (d) "치수 맞추기 부자연" 단점 회피
- 출처 정정: 클리앙 글에서 "버벅이고 치수 맞추기가 부자연스럽다"는 말은 댓글 작성자가 **오늘의집 3D**를 두고 한 말이다. 본문은 Floorplanner를 "빠르고 최적화가 잘 됨, 수치 기반 정밀 작성"으로 평가했고, Floorplanner 단점은 렌더 품질·속도와 무료판 기능 제한이었다.
- 우리 원칙: 숫자 입력이 1순위, 끌기는 보조.
  - 모든 길이는 숫자 칸(mm, 숫자 자판 `inputmode="numeric"`)으로 입력.
  - 끌기는 보기 이동·확대에만 쓰고, 도형 변경 끌기는 넣더라도 10mm 단위 자석 + 놓으면 숫자 칸에 값 표시.
  - 그림을 누르면 해당 벽·구멍의 숫자 칸으로 이동(그림 = 선택 도구, 숫자 = 편집 도구).
  - 3D 없음 → 휴대폰에서 무겁지 않게.

## 4. 공용 설계안

### 4-1. 평면 편집기 핵심(core) — `src/components/plan/`

| 부분 | 내용 |
|---|---|
| 도형 모델 | 방 = 꼭짓점 목록(mm, 시계 방향). 벽 = 꼭짓점 i → i+1 변, 벽 번호 = i+1. 구멍(문·창) = 벽 번호 + 시작 위치(벽 시작점에서 mm) + 폭 (+높이·바닥에서 높이) |
| 입력 | 사각형(가로·세로) / ㄱ자 / 자유형(벽 길이 + 꺾는 방향 차례 입력) → 꼭짓점 목록으로 변환. 닫힘 오차 표시 |
| 보기 | SVG `viewBox` 로 확대·축소·이동(두 손가락 확대, 한 손가락 이동, "전체 보기" 버튼) |
| 치수선 | 벽마다 바깥쪽에 치수선+숫자, 구멍은 벽 위 위치·폭 치수 |
| 내보내기 | SVG → 캔버스 → PNG 저장(외부 라이브러리 없이) |
| 주소 공유 | 도형+플러그인 설정을 짧은 JSON → 압축 없이 base64url 로 주소 뒤에 붙임. 길어지면 숫자 배열 형식으로 줄임 |
| 플러그인 자리 | core는 방·벽·구멍만 그리고, 그 위 덧그림 층과 옆 입력칸·결과표는 플러그인이 채움 |

### 4-2. 플러그인

| 플러그인 | 입력 | 그림 | 결과 |
|---|---|---|---|
| 타일 | 바닥/벽 선택, 규격(가로·세로 mm), 줄눈, 패턴(일자·지그재그 1/2·1/3·대각), 시작 기준(가운데/모서리), 박스당 장 수 | 바닥 배치도, 벽 전개도(벽 번호 순서로 펼침, 문·창 구멍 빼고) | 온장/컷 장 수, 로스율, 박스, 줄눈재, 접착제, 컷 묶음 목록 |
| 붙박이장 | 벽 하나 고르기, 천장 높이, 깊이, 칸 수(또는 칸 폭), 문 종류(여닫이/미닫이), 판재 두께 | 고른 벽의 정면도(칸·문짝) | 판재 절단 목록, 원장 장 수, 문짝 수, 경첩 수 |
| 냉장고장 | 벽 하나 고르기, 냉장고 폭·높이·깊이(또는 모델 프리셋), 여유 간격, 양옆 키큰장 폭 | 정면도(냉장고 자리 + 키큰장 + 위 상부장) | 판재 절단 목록, 원장 장 수, 문짝 수 |

### 4-3. 플러그인 연결 모양(예시)

```ts
// 도면 핵심이 넘겨주는 공용 도형 (단위: mm)
type Pt = { x: number; y: number };
type Opening = { wall: number; start: number; width: number; height?: number; sill?: number; kind: "door" | "window" };
type Plan = { pts: Pt[]; openings: Opening[]; ceiling?: number };

// 각 계산기 플러그인이 지켜야 하는 약속
interface PlanPlugin<S, R> {
  id: "tile" | "closet" | "fridge";
  defaults: S;                              // 처음 설정값
  compute(plan: Plan, s: S): R;             // 순수 계산 (화면과 분리, 시험 쉽게)
  Overlay(p: { plan: Plan; s: S; r: R }): JSX.Element;  // SVG 덧그림
  Panel(p: { s: S; set(s: S): void }): JSX.Element;     // 입력칸
  Result(p: { r: R }): JSX.Element;                     // 결과표
  encode(s: S): string; decode(q: string): S;           // 주소 공유
}
```

### 4-4. 입력 두 입구 — "숫자 입력"과 "사진으로 치수 채우기"

형아 옛 기획 "딱구"(공간 사진 + 아는 높이 기준선 1개 → 원근 보정 → 가로 치수 산출 → 도면)를 나중에 붙일 수 있게, 도면 핵심의 입력을 두 입구로 나눈다. 두 입구 모두 **같은 도형 모델**(방 꼭짓점·벽·문/창)로 들어오고, 그 뒤(타일·붙박이장·냉장고장 플러그인)는 입구를 모른다.

| 입구 | 지금 | 하는 일 | 결과 |
|---|---|---|---|
| 1. 숫자 입력 | 구현됨(타일 물량 계산기) | 사각형·ㄱ자·자유형 + 문·창 숫자 칸 | `ShapeInput` + `Opening[]` |
| 2. 사진으로 치수 채우기 | 나중(플러그인) | 벽면 사진 → 네 모서리 찍기 → 원근 보정(사진 속 사각형을 정면 사각형으로 펴기) → 아는 높이 1개(예: 문 높이 2,100 또는 천장 2,300)로 축척 → 가로·문/창 위치 산출 | 아래 데이터 모양으로 넘김 → 숫자 칸에 미리 채움 |

사진 쪽이 넘겨줄 데이터 모양(벽면 하나 단위, mm):

```ts
type PhotoWallMeasure = {
  wall: number;              // 도면 벽 번호(0부터) — 사용자가 "이 사진은 벽 2" 하고 고름
  width: number;             // 벽면 폭
  height: number;            // 벽면 높이(시공 높이 후보)
  openings: { kind: "door" | "window"; offset: number; width: number; height: number; sill: number }[];
  source: "photo";           // 숫자 입력값과 구분하는 표시
  refLine: { label: string; mm: number };   // 축척 기준(예: 문 높이 2,100)
  confidence: "low" | "mid"; // 기준선 1개 + 원근 보정이라 높을 수 없음
};
```

- 화면 표시: 사진에서 온 값은 숫자 칸 옆에 **"실측 전 예상"** 작은 글자(회색)를 붙이고, 도면 치수선도 점선으로 그린다. 사용자가 그 칸을 한 번 고치면 표시가 사라진다(실측값으로 본다).
- 물량표에도 "실측 전 예상 치수 포함" 한 줄을 붙인다(주문은 실측 뒤에).
- 방 전체 모양(꺾임)은 사진 한 장으로 알 수 없으므로, 방 모양은 숫자 입구에서 고르고 벽면 폭·높이·문/창만 사진으로 채운다.
- 원근 보정 계산(네 점 → 평면 사상 행렬)은 외부 라이브러리 없이 순수 함수로 짤 수 있다(8개 미지수 1차 연립방정식). 사진은 서버에 올리지 않고 브라우저 안에서만 처리하는 것을 원칙으로.

### 4-5. 1차 구현 결과(2026년 10월 28일, 브랜치 feat/tile-pro)

| 파일 | 역할 |
|---|---|
| `src/components/plan/geometry.ts` | 도형 모델·방 만들기(사각형/ㄱ자/자유형)·넓이·둘레·바깥 방향·다각형 자르기(순수 함수) |
| `src/components/plan/PlanCanvas.tsx` | SVG 그림판: 벽선·치수선·벽 번호·문(여닫이 호)·창(겹선)·구멍, 확대/축소/맞춤·두 손가락·확대 시 끌어 이동. `children` 함수로 플러그인 그림을 받아 방 모양으로 잘라 보여 줌 |
| `src/components/plan/RoomShapeInput.tsx` · `OpeningsInput.tsx` · `MmField.tsx` | 숫자 입구(방 모양·문/창·mm 칸) |
