## 6. 처리 방식 제안

1. 합치기(4편, 기다림 1편 별도): 남길 글에 이전 글의 고유 표·사례만 이전 → 이전 글 md 삭제 → next.config 리다이렉트에 301 추가 → 사이트맵에서 자동 제외(글 목록 기반이면 삭제로 해결) → 남길 글에서 서치콘솔 색인 재요청. 이전 글에 다른 글이 건 내부 링크는 남길 글로 치환.
2. 보강(기본 방향): 얇은 글은 실견적 사례·표·FAQ를 늘리고, 같은 묶음의 노출 있는 글에서 본문 중간 내부 링크를 걸고(링크 받는 쪽도 추가), 보강 후 URL 검사로 색인 요청. 수집됨-미색인 글(plumbing-cost, lighting-replacement-cost)은 제목·도입부를 새로 쓰는 수준으로.
3. c 4편: 보강 맨 마지막 순번. 그래도 노출 0이면 noindex 후보(삭제는 하지 않음).
4. 하루 처리량 = 하루 2편(새벽 보강 작업에 편입, 5시간 창 안, 낮 배치 금지).
5. URL 검사 API 한도는 하루 2,000건이라 여유. 보강한 글 재검사는 2주 뒤 일괄.
