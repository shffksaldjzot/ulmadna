## 2. 원인 (코드)

### 2-1. 블로그 글 60초 재생성 — 주범

- `src/app/blog/[slug]/page.tsx` 는 `generateStaticParams` 로 **정적 생성**되는 페이지(글 361편).
- 그 안에서 `getCachedPostTotals(slug)` 를 부르는데, 이 함수는 `src/server/metrics/blogLike.ts` 34~38줄의 `unstable_cache(..., { revalidate: 60 })`.
- Next.js 규칙: 페이지 안에서 쓴 fetch·unstable_cache 의 **가장 짧은 revalidate 가 그 페이지의 재생성 주기**가 된다 → 글 361편 전부가 "60초 ISR" 페이지가 됐다. (10-27 Upstash → 수파베이스 이전 때 들어온 설정. 당시 주석에도 "60초마다 뒤에서 다시 만들어지는(ISR)" 이라 적혀 있음 — 요청 3번을 0번으로 줄인 건 맞지만, 재생성 비용은 못 봤다.)
- 셈: 하루 9만 회 ÷ 361편 ≈ 글당 250번/일 ≈ 6분마다 [어림]. 사람 방문(계산기 하루 약 100회 수준)보다 훨씬 많아 **검색엔진·AI 수집기가 글을 훑는 주기**로 보임 [추정].
- 부수 비용: 재생성 1번 = 함수 1번 실행(마크다운 → HTML) → Fluid CPU $1.21·메모리 $0.57 의 상당 부분, Observability 이벤트도 같이 늘어남.
